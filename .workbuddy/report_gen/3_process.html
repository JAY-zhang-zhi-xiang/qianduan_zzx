（3）实现一：SVG 符号雪碧图（方案 A）

index.html、zone.html、chat.html、mine.html 四个页面采用 SVG 方案。做法是在文档顶部放一个隐藏的 <svg>，用 <symbol id="zzx-ico-home"> 这样的定义把 5 个图标的路径存起来，导航里再用 <svg><use href="#zzx-ico-home"></use></svg> 引用。这样 5 个图标只需在页面中出现一次，多处复用等于零成本，且不用额外请求图片文件。

图标颜色通过 fill: currentColor 交给 CSS 的 color 控制，大小通过 width / height 控制，因此同一份图标既能做灰色未选中态，也能做黑色选中态，不需要准备两套图片。

另一个细节是视觉尺寸的统一：不同来源的图标在 1024 的画布里留白不一样，直接同尺寸显示会一大一小。实现时先用 <use> 的 getBBox() 量出每个图标墨迹的实际包围盒，再用 <g transform="translate(x y) scale(k)"> 把墨迹统一缩放到 1024 画布的 920 单位以内，五个图标因此在同一个 23px 的方框里看起来一样大。

图 4  SVG 版下导航特写（1 倍尺寸放大 2 倍显示）

（4）实现二：字体图标 font-class（方案 B）

按实验要求“使用字体图标或 SVG，要求和上一步中的技术有区别”，方案 A 用了 SVG，方案 B 就必须用字体图标。nav-fontclass.html 复用同一套 CSS 布局，只把图标承载方式换掉：把项目导出的 iconfont.woff2、woff、ttf 放入 font/ 目录，在 css/iconfont.css 中用 @font-face 引入，导航里写 <i class="iconfont icon-index-copy"></i>。图标于是变成了一个字符：大小由 font-size 控制，颜色由 color 控制，二者都跟随 CSS 变量。

这里有一个必须处理的问题：iconfont 生成的 .iconfont 基类把 font-size 写成了 16px !important，直接写 .zzx-tabbar__font 无法覆盖。解决办法是用“.zzx-tabbar__font.iconfont”两个类名提高选择器优先级，再用 !important 顶掉基类的 !important，尺寸才能真正由 --zzx-nav-icon 变量统一控制。

（5）自适应宽度、固定定位与凸起按钮

自适应宽度用弹性盒实现：普通 tab 写 flex: 1 1 0 并配 min-width: 0，四项按可用宽度均分，中间按钮写 flex: 0 0 auto 加固定 48px 宽度，因此无论视口是 320 还是 1440，导航条都不会出现横向滚动或挤压。固定效果用 position: fixed; left/right/bottom: 0 实现，并加 padding-bottom: env(safe-area-inset-bottom, 0px) 适配 iPhone 全面屏的底部安全区。

中间按钮的凸起用 transform: translateY(-8px) 实现，父级刻意不设置 overflow: hidden，否则凸出部分会被裁掉。内容区宽度用 --zzx-page: 750px 限制并居中，页面本体则始终铺满窗口，这样在桌面浏览器下内容是居中的阅读栏，两侧是白底而不是灰边。
